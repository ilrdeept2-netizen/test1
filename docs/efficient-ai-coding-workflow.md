# 상위 1% 엔지니어의 AI 코딩 워크플로우

> 바퀴를 다시 발명할 시간이 없다. 좋은 부품을 찾아 조립하게 시키자.

## 핵심 원칙

기획서(Spec)가 나왔다고 바로 코딩 에이전트에게 던지지 마라.

## 문제

- AI는 학습된 과거 데이터에 갇혀 있거나, 이미 있는 기능을 처음부터 직접 만들려는 경향이 있다.
- 검증된 라이브러리 대신 자체 구현을 시도하면 구형 패턴, 버그, 유지보수 부채가 쌓인다.

## 워크플로우

### Step 1: 패키지 리서치 먼저

기획서를 복사해서 ChatGPT(Heavy Thinking 모드) 등 리서치용 AI에게 먼저 질문한다.

**프롬프트 예시:**

```
이 기능 구현할 건데, 유지보수 잘 되고 커뮤니티 활발한 최신 GitHub 패키지 찾아줘.
단, Next.js랑 완벽하게 호환되는 걸로만 골라줘.
```

### Step 2: 패키지 리스트를 코딩 에이전트에 전달

리서치 결과로 얻은 검증된 패키지 목록을 코딩 에이전트 컨텍스트에 포함시킨다.

### Step 3: 구현

검증된 도구를 손에 쥔 에이전트는 맨땅에 헤딩하는 주니어가 아닌, 좋은 부품을 조립하는 시니어 개발자처럼 동작한다.

## 왜 효과적인가

| 항목 | 리서치 없이 바로 코딩 | 리서치 후 코딩 |
|------|----------------------|---------------|
| 패키지 선택 | 학습 데이터 기반 (구형 가능) | 최신, 커뮤니티 검증 |
| 구현 방식 | 자체 구현 시도 | 기존 라이브러리 활용 |
| 디버깅 시간 | 수 시간 | 최소화 |
| 유지보수성 | 낮음 | 높음 |

## 요약

**검색 5분 투자가 나중에 몇 시간의 구형 라이브러리 디버깅을 막아준다.**

1. Spec 받으면 → 리서치 AI로 패키지 탐색
2. 검증된 패키지 리스트 확보
3. 코딩 에이전트에게 패키지 리스트와 함께 구현 지시
