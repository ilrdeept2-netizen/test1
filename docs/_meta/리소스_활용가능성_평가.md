# 공유 리소스 활용가능성 전수 평가

> **관점**: 사용자가 공유한 스레드·유튜브·웹 주소를 단순 "정보 파악"이 아니라
> **"이 핵심을 내 웹앱 또는 로컬(Codex·Claude Code) 환경에 도입해서 실제로 활용 가능한가"** 로 판정.
>
> 이 레포의 `docs/` 가 그동안 공유된 리소스의 영구 기록이므로, 전체 40개 문서를 이 관점으로 전수 평가했다.
> (참고: Claude Code 세션은 채팅 로그가 세션 간 보존되지 않음 → `docs/` 가 곧 "대화에서 준 주소들"의 누적 산출물.)

**범례**: ✅ 도입가능 · 🔶 부분/조건부 · ❌ 해당없음(단순정보)

---

## 1. 즉시 도입 추천 (✅ — 설정/구조 변경만으로 흡수 가능)

이 그룹이 당신 질문의 핵심 답이다. **거의 전부 로컬(Claude Code/Cowork) 도입 대상**이며, 특허 도메인 자동화로 바로 연결된다.

| 리소스 | 핵심 | 도입대상 | 구체적 액션 |
|--------|------|----------|-------------|
| **LLM WIKI (Cowork/ClaudeCode 도입)** | 자동 압축 컨텍스트 손실 방지용 `wiki/` + CLAUDE.md 게이트웨이(100줄 제한) | 로컬 | **최우선.** CLAUDE.md를 진입점으로, `wiki/`(INDEX·decisions·errors·patterns·domain·snapshots) 구성 → 세션 간 특허 도메인 지식 영구 유지 |
| **LLM WIKI (AG 도입)** | Karpathy LLM WIKI를 세션 메모 시스템으로 | 로컬 | `.claude/hooks/session-start.sh` + `wiki/` 도입. decisions=청구항 전략, errors=HWP 파싱오류, patterns=번역규칙 |
| **Claude Cowork 특허 프롬프트 가이드** | 발명분석→명세서→청구항→OA대응 11모듈 프롬프트 | 로컬 | 즉시. "20년차 변리사 역할 + 4대 원칙" 설정 후 11단계 순차 실행으로 전체 워크플로우 자동화 |
| **Claude Code Agent Teams** | 리드 에이전트가 팀원 병렬 실행 | 로컬 | `settings.json`에 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS:"1"` → 선행기술·청구항·도면 병렬 검토 |
| **Obsidian × Claude Code 연동** | MCP 없이 로컬 볼트 직접 접근, 토큰 절약 | 로컬 | `additionalDirectories:["/Obsidian경로"]` 1줄 추가 → 개인 지식베이스 즉시 연결 |
| **AskUserQuestion 가이드** | 작업 중 구조화된 선택형 질문 | 로컬 | 명세서 작성 시 "청구항 전략" 등을 선택형으로 제시, Plan Mode와 병용 |
| **Scheduled Tasks 가이드** | 반복작업 자동화 | 로컬 | OA 수신 주간 점검, 포트폴리오 기한 월간 감시 + 알림 예약 |
| **Cowork 리걸플러그인 특허 활용** | 신호등(녹/황/적) 패턴을 청구항 평가에 차용 | 로컬 | 커스텀 Skill `/check-specification`, `/review-oa` 개발 + KIPRIS MCP 연동 |
| **플러그인 정리 및 특허 활용** | 레포 5개 도구를 Skill로 래핑 | 로컬 | 각 도구를 `/patent-review`, `/prior-art-search` Skill화 |
| **플러그인·MCP 연동 정리** | MCP로 외부 DB/도구 연결 | 로컬 | SQLite MCP로 특허DB 쿼리, KIPRIS API MCP 개발, Slack MCP 알림 |
| **DeerFlow (ByteDance)** | 오픈소스 멀티에이전트 하네스, 마크다운 스킬 시스템 | 둘다 | 로컬: 서브태스크 분해 아키텍처 차용. 웹앱: 멀티에이전트 오케스트레이션 패턴 |
| **바이브코딩 도구 총정리 2026** | Claude Code/Lovable/v0/Bolt 생태계 지도 | 둘다 | 웹앱: v0·Bolt 스타일 자연어→프론트엔드 파이프라인. 로컬: Claude Code 도메인 특화 확대 |
| **Antigravity 사용량·모델 가이드** | AI Ultra 한도(하루 2000회), 모델 선택 기준 | 둘다 | Gemini vs Claude 모델 선택 근거로 활용 |
| **Show Me 시각화 분석** (session-2026-03-15) | 인라인 자동생성 시각화 UX 패러다임 | 웹앱 | 웹앱 데이터 시각화 UI 설계에 Show Me 패러다임 적용 |
| **fix_cowork_vhdx_access.ps1** | Windows Cowork VM 권한 자동수정 | 로컬 | Windows 사용 시 최초 1회 실행, 한글경로→ASCII(C:\ClaudeVM) 마이그레이션 |
| **Cowork 윈도우 배포/심층 가이드** | 서브에이전트 병렬·DAG·로컬상태 | 로컬 | Cowork(mac)/Claude Code(win) 선택 후 특허 폴더 지정, 병렬 청구항 검토 |

## 3. 해당없음 — 순수 정보/뉴스/개인기록 (❌ 도입 대상 아님)

기술 흡수 대상이 아닌, 정보 파악·아카이브 목적의 문서. (관점상 "도입" 항목에서 제외하되 지식 DB로는 유지)

- **Claude Code 아키텍처 분석** — 내부 설계 이해용(직접 도입 기능 없음, 향후 플러그인 참고)
- **클로드코드 vs 웹앱 UX 비교** — 도구 선택 기준 참고(흡수 기능 없음)
- **antigravity_connection_test** — 일회성 연결 테스트 기록
- **GPT5.2 글루온진폭** — 순수 과학 사례
- **한화솔루션 유상증자** / **중동분쟁 요약** / **이란전쟁 유가 TACO** — 시사·금융 아카이브
- **WoW PVP 티어리스트/가이드/힐러분석** (3건) — 게임 공략
- **리나 건강이력** / **한울 고구마스틱 보관법** — 개인 기록

## 📌 최종 결론 — "내 환경에 도입한다면" 로드맵

**로컬(Claude Code/Cowork) = 특허 도메인 깊이 있는 자동화** 방향:
1. **LLM WIKI 구조 수립** (CLAUDE.md + `wiki/`) ← 모든 것의 토대, 최우선
2. **특허 프롬프트 11모듈** + **커스텀 Skills**(`/check-specification` 등)
3. **Agent Teams** 활성화 + **Obsidian 연동**(각각 1줄 설정)
4. **MCP 개발**(KIPRIS·SQLite·Slack) + **Scheduled Tasks**(기한 감시)

**웹앱 = 협업 + 데이터 통합 + 시각화** 방향:
- DeerFlow 멀티에이전트 패턴 · v0/Bolt 프론트엔드 자동화 · Show Me 인라인 시각화 · (조건부) Gemini Workspace

> 즉, **즉시 효과 큰 것 = LLM WIKI + 특허 프롬프트 가이드 + Agent Teams/Obsidian 설정**.
> 이 3가지만 적용해도 로컬 환경이 "단순 챗 래퍼"에서 "특허 실무 자동화 워크벤치"로 전환된다.
